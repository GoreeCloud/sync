# Padded offline inventory envelope v2 — local candidate

**Purpose:** GoreeShield metadata privacy for offline file inventories. This design does not replace GoreeCloud Identity's Ed25519 trusted-peer verification or Wardveil's authenticated encryption. No source has been deployed or verified on physical devices.

The exporter signs the inventory in memory, places a 4-byte unsigned big-endian length before its canonical signed JSON, then adds unpredictable bytes from the OS cryptographic random source until the resulting plaintext is a multiple of **65,536 bytes**. The complete padded plaintext is encrypted under AES-256-GCM with a fresh random 96-bit nonce and purpose-separated AAD `GoreeCloud Sync encrypted offline inventory v2 padded`. The outer JSON includes only version (`2`), algorithm, nonce and ciphertext. Signed data, filenames, hashes and the exact plaintext length are authenticated inside the encrypted payload. The exported file remains 0600, no-overwrite, outside the scanned folder. The shared 256-bit key remains in its separate private file; the key is never printed.

The recipient verifies the GCM tag before accepting the authenticated length, rejects invalid bucket or length bounds, then checks the Ed25519 signature against an independently trusted pinned peer key and any signed challenge/one-use ticket. **Authenticated legacy encrypted v1 envelopes** remain readable under the original AAD, but new exports always use v2. Plaintext files are never accepted by encrypted mode. Changing `version` without re-encrypting invalidates authentication.

**Privacy limits:** Small inventories of different sizes that fit into one bucket now have equal-length ciphertext fields. The envelope still reveals bucket count and exchange timing. This is *length-hiding*, not traffic analysis resistance, full anonymity, automatic key distribution, or hidden sender identity from a verifier. Random padding adds up to 65,535 bytes per exchange; repeated exports can differ in ciphertext even when the file set is identical. The local key, memory, backups, crash dumps and compromised peers remain risks. Existing inventory scans are not atomic filesystem snapshots; the one-use replay marker remains vulnerable to deliberate rollback/deletion.

**Verification:** `go test -race ./internal/syncplan -run 'TestPaddedConfidential|TestLegacyConfidential|TestConfidential' -count=1` and `bash tests/confidential-offline-cli.sh`. This is an experimental source-only feature. GitHub publication, licensing, hosted CI, platform-native client installation and two-device tests are separate outstanding acceptance gates.
